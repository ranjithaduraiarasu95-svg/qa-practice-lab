The page under test. Try to break it.

Scenario 1: Login form

Level: Beginner

Valid credentials

Email: tester@qalab.dev
Password: Test@1234

Skills practiced: locators (id, name, data-testid), typing, clicking, asserting text, checking element visibility and attributes.

Test cases to write

Valid login

Enter valid email and password, click Sign in. Expect the welcome panel and a Log out button.

Wrong password

Valid email, wrong password. Expect the message “Invalid email or password.” and no welcome panel.

Unknown email

Use nobody@example.com. Same generic error message as a wrong password.

Empty fields

Click Sign in with both fields empty. Expect “Email is required.” and “Password is required.”

Email format

Enter testerqalab.dev. Expect “Enter a valid email address.”

Show / hide password

Type a password, click Show. The input type changes from password to text, and the button text becomes Hide.

Whitespace around email

Enter a valid email with spaces before and after. Expect login to succeed (input is trimmed).

Case sensitivity

Email is not case sensitive. Password is case sensitive.

Remember me

Check the box, log in, then log out. The email field should come back pre-filled. Uncheck it and the field stays empty.

Logout

After logging in, click Log out. The form returns, and the password field is empty.

Scenario 2: Registration form

Level: Beginner

Already registered emails: tester@qalab.dev, admin@qalab.dev, taken@qalab.dev

Skills practiced: form filling, inline error assertions, checkbox handling, boundary values, negative testing, dynamic text checks.

Test cases to write

Valid registration

Fill every field correctly, accept the terms, submit. Expect “Account created successfully. Welcome, <name>!”

All fields empty

Click Create account. Expect a required error under every field and under the terms checkbox.

Name rules

Try 1 character, 51 characters, digits (John123) and symbols. Valid: Mary-Ann O’Neil. Spaces around the name are trimmed.

Email format

Try abc, abc@, abc@x, and a b@x.com. Expect “Enter a valid email address.”

Duplicate email

Use a registered email, also in UPPERCASE. Expect “This email is already registered.”

Password rules

Test each rule alone: too short, too long (21), no uppercase, no lowercase, no number, no special character. The rule list turns green as each rule is met.

Password boundaries

Exactly 8 characters and exactly 20 characters should pass. 7 and 21 should fail.

Confirm password

Different value gives “Passwords do not match.” Same value passes.

Terms checkbox

Everything valid but terms unchecked. Expect “You must accept the terms.”

Register another user

After success, click Register another user. The form comes back fully empty.

Scenario 3: Checkboxes and radio buttons

Level: Beginner

Skills practiced: check, uncheck, isChecked, isEnabled, radio groups, indeterminate state, default values, disabled elements, form submission.

Test cases to write

Default states

On page load, only Manual testing is checked. Beginner is the selected level. No tool is selected. Counter reads “1 of 5 selected”.

Check and uncheck

Check Automation, then uncheck it. State and counter update each time.

Select all

Click Select all. All 5 interests are checked and the counter reads “5 of 5 selected”. Click again and all are unchecked.

Select all, partial state

With some interests checked, Select all shows the indeterminate state (the indeterminate property is true). Checking the last one makes it fully checked.

Disabled elements

Chaos engineering and Expert cannot be clicked. Assert disabled and that the state does not change after a click attempt.

Radio group behaviour

Select Intermediate. Beginner becomes unselected. Only one level can be selected at a time.

Radio cannot be unselected

Click a selected radio again. It stays selected. Only Reset or a different choice changes it.

Label click

Click the label text, not the box. The matching input changes state.

Validation

Uncheck all interests and click Save. Expect “Select at least one interest.” Without a tool, expect “Choose a test tool.”

Save and reset

Valid save shows a summary line with your choices. Reset restores every default and hides the summary.
